## Implementation notes

- Per-window `State` (model chain, hidden flag, back/forward stacks) holds no widgets. Closures can keep it alive without a reference cycle through the window.
- Changing `Listing::file` destroys the focused item widget, which leaves focus nowhere. `State::show` grabs focus on the visible view after every change (`NAV-30`). See also `KEY-3`.
- `NAV-13`: `gtk::DirectoryList` cannot be used for the listing. Its monitor queues one event per change and waits for each event's `query_info`. When that fails because the file is already gone, the failed event stays at the head of the queue and every later change is dropped, so the window stops refreshing until a reload. The window uses its own `listing::Listing`, which handles each event on its own.
- `NAV-15`: `State::reveal` holds an item to select once it is listed. It is checked on every `items_changed` (in an idle, not inside the signal) and given up when loading ends without it.
